# Configuration

## Where settings live

| Setting | Where | Notes |
|---|---|---|
| `ConnectionStrings:DefaultConnection` | `appsettings.Development.json` (LocalDB, no password) | Override with user secrets or `ConnectionStrings__DefaultConnection` to use another SQL Server |
| `Jwt:Issuer`, `Jwt:Audience` | `appsettings.json` | Not secret |
| `Jwt:Key` | **User secrets** (generated by `scripts/setup.ps1`) | Required, 32+ characters. Never commit it |
| `Seed:AdminEmail`, `Seed:AdminPassword`, `Seed:AdminName` | **User secrets** | Optional. The admin is created at startup if set |
| `Cors:AllowedOrigins` | `appsettings.json` | Defaults to the Blazor dev origin |
| `Database:MigrateOnStartup` | environment | `true` migrates on startup outside Development (used by Docker Compose) |
| `ApiSettings:BaseUrl` | `BlazorWebAssemblyApp/wwwroot/appsettings.json` | Public by nature: it is downloaded by the browser |

In any non-Development environment the secrets come from environment variables (`Jwt__Key`, `Seed__AdminPassword`, ...) or your host's secret store.

## Local development (Windows)

- **Prerequisites:** the [.NET 10 SDK](https://dotnet.microsoft.com/download) and SQL Server LocalDB (installed with Visual Studio's web or data workloads, or with SQL Server Express). Development uses `(localdb)\MSSQLLocalDB` and creates the `AuthorBooksDb` database for you.
- **Secrets:** `powershell -File scripts/setup.ps1` writes a random `Jwt:Key` and an admin login into user secrets and prints the admin credentials once. Show them again with `dotnet user-secrets list --project IdentityManagerServerApi`. It never overwrites existing secrets, so it is safe to re-run.
- **Trust the dev certificate** once if needed: `dotnet dev-certs https --trust`.
- **Another SQL Server (or no LocalDB):** point `ConnectionStrings__DefaultConnection` at it.
- **Reset the database:** `dotnet ef database drop --project IdentityManagerServerApi`, then start the API again.
- **Migrations outside Development:** the API only auto-migrates in Development (or with `Database:MigrateOnStartup=true`). Elsewhere run `dotnet ef database update --project IdentityManagerServerApi`, or generate a script with `dotnet ef migrations script --idempotent`.
- **Password reset:** there is no email sender. In Development the reset token is written to the API console log; paste it into the reset page.

## Docker

- `cp .env.example .env`, fill in `JWT_KEY`, `ADMIN_PASSWORD` and `SA_PASSWORD`, then `docker compose up --build`.
- `.env` is git-ignored, and compose refuses to start while any of those values is unset, so there are no default credentials.
- Client <http://localhost:8081>, API <http://localhost:8080> (`/health` checks the database, `/health/live` does not). Data lives in the `sqldata` volume; `docker compose down -v` wipes it.
- If ports 8080 or 8081 are taken, change the `ports:` mappings in `docker-compose.yml`, the `Cors__AllowedOrigins__0` value and `docker/client-appsettings.json` together.
- The API runs in the Production environment there: Swagger is off and password-reset tokens are never exposed. It is a local demo stack over plain HTTP, not a hardened deployment.

## Tests

`dotnet test AuthorBooksBlazorCore.Test`: in-memory SQLite, so no database or secrets are needed.
